# class12~class13 二叉树代码学习总结（排除 Code05）

## 1. 总体主题

class12~class13 这一段代码，核心其实是在讲一类非常重要的二叉树套路：

> **树形 DP / 递归套路**

也就是：

- 对于每一棵子树，先向左树和右树要信息；
- 再把左右子树的信息，整理成当前节点的信息；
- 最后一路向上汇总，得到整棵树的答案。

这套方法几乎贯穿了本节所有题目。

从代码风格上看，基本都遵循同一个模板：

1. 定义节点 `Node`
2. 写一个暴力或对数器版本（`xxx1`）
3. 写一个正式递归版本（`xxx2`）
4. 定义 `Info` 类，表示“某棵子树返回给父节点的信息”
5. 在 `process(x)` 中：
   - 收集左树信息
   - 收集右树信息
   - 组合出当前树信息
6. 用随机树大量测试两个版本是否一致

所以，这两章真正要学会的，不只是某一道题，而是：

> **如何设计子树需要上报的信息 Info。**

## 3. 二叉树基础概念补充

这部分是给整份代码总结补地基的。很多后面的题，如果这些概念不稳，就会越学越乱。

### 3.1 什么是二叉树

二叉树是一种树结构，每个节点最多只有两个孩子：

- 左孩子 `left`
- 右孩子 `right`

例如：

```text
      1
     / \
    2   3
   / \
  4   5
```

这里：

- `1` 是根节点
- `2` 是 `1` 的左孩子
- `3` 是 `1` 的右孩子
- `4、5` 是叶子节点

### 3.2 常见术语

#### 根节点 Root
整棵树最上面的节点。

#### 父节点 / 子节点
如果节点 A 连着节点 B，且 A 在上、B 在下：

- A 是 B 的父节点
- B 是 A 的子节点

#### 左子树 / 右子树
一个节点往左连出的整片结构叫左子树，往右连出的整片结构叫右子树。

#### 叶子节点 Leaf
没有任何孩子的节点。

#### 空树
一个节点都没有的树，通常用 `null` 表示。

### 3.3 节点的度

节点有几个孩子，它的度就是几。

- 度为 0：叶子节点
- 度为 1：只有一个孩子
- 度为 2：有两个孩子

二叉树里每个节点的度最多为 2。

### 3.4 层数、高度、深度

这是最容易混的。

#### 层数
根节点一般记为第 1 层。

#### 深度
从根节点走到当前节点，所在的层数。

#### 高度
从当前节点往下，到最深叶子节点，一共能延伸多少层。

例如：

```text
      1
     / \
    2   3
   / \
  4   5
```

- `4` 的高度是 1
- `2` 的高度是 2
- 整棵树的高度是 3

在你这两章代码里，`height` 基本都表示：

> **以当前节点为头的子树高度。**

### 3.5 遍历方式

#### 先序遍历
顺序：

```text
头 -> 左 -> 右
```

#### 中序遍历
顺序：

```text
左 -> 头 -> 右
```

#### 后序遍历
顺序：

```text
左 -> 右 -> 头
```

#### 层序遍历
按层从左到右遍历，通常配合队列。

你在 `Code01_IsCBT` 里看到的，就是层序遍历判断完全二叉树。

### 3.6 子树

对于任意节点 `x`：

> 以 `x` 为头、下面整片结构组成的一棵树，就叫 `x` 的子树。

这句话是树形 DP 的起点。因为所有 `process(x)` 的含义，本质上都是：

> 处理以 `x` 为头的整棵子树，并向父节点返回结果。

### 3.7 路径与距离

#### 路径
从一个节点沿树边走到另一个节点的路线。

#### 距离
这套代码里，距离按**路径上节点个数**来算。

例如路径：

```text
4 -> 2 -> 1 -> 3
```

经过 4 个节点，所以距离是 4。

#### 最大距离
树中任意两个节点之间路径长度的最大值，也就是常说的“树的直径”。

### 3.8 祖先与最低公共祖先

#### 祖先
如果节点 A 在节点 B 到根节点的路径上，那么 A 是 B 的祖先。

#### 最低公共祖先 LCA
两个节点共同祖先里，离它们最近的那个。

例如：

- `4` 和 `5` 的最低公共祖先是 `2`
- `4` 和 `3` 的最低公共祖先是 `1`

### 3.9 四种最容易混淆的树

#### 满二叉树 Full Binary Tree
每一层都满。

如果高度为 `h`，节点数一定满足：

```text
2^h - 1
```

#### 完全二叉树 Complete Binary Tree
除最后一层外都满；最后一层从左往右连续。

#### 平衡二叉树 Balanced Binary Tree
任意节点的左右子树高度差不超过 1。

#### 搜索二叉树 BST
- 左子树所有节点都小于根
- 右子树所有节点都大于根
- 左右子树本身也必须是 BST

而且 BST 的中序遍历结果一定严格递增。

### 3.10 基础概念和本章题目的对应关系

- 完全二叉树：`src/class12/Code01_IsCBT.java`、`src/class13/Code01_IsCBT.java`
- 平衡二叉树：`src/class12/Code03_IsBalanced.java`
- 搜索二叉树：`src/class12/Code02_IsBST.java`
- 最大距离：`src/class12/Code06_MaxDistance.java`
- 最低公共祖先：`src/class13/Code03_lowestAncestor.java`
- 最大搜索子树：`src/class13/Code02_MaxSubBSTHead.java`

## 4. 贯穿所有题目的核心方法：树形 DP

### 4.1 为什么树题适合递归

因为树天然就是递归结构：

- 一棵树 = 根节点 + 左子树 + 右子树
- 左子树和右子树本身又是树

所以很多题都可以变成：

> “如果我已经知道左子树答案、右子树答案，那么当前节点答案怎么求？”

这就是树形 DP。

### 4.2 树形 DP 的标准模板

```java
public static Info process(Node x) {
    if (x == null) {
        return baseInfo;
    }
    Info leftInfo = process(x.left);
    Info rightInfo = process(x.right);

    // 利用左右子树信息，整理当前节点的信息
    ...

    return new Info(...);
}
```

关键不在递归本身，而在于：

> **当前节点到底需要从左右子树获得哪些信息？**

Info 设计对了，题就出来了；Info 设计错了，题就很难写。

## 5. Code01_IsCBT：判断完全二叉树

文件：

- `src/class12/Code01_IsCBT.java`
- `src/class13/Code01_IsCBT.java`

这两个文件本质是同一道题，class13 版写得更精炼。

---

### 5.1 什么是完全二叉树

完全二叉树（CBT）要求：

- 除最后一层外，前面每层都满；
- 最后一层的节点必须从左往右依次排满。

典型违规情况：

- 某节点 **只有右孩子，没有左孩子**；
- 一旦出现“不双全”的节点后，后面还出现非叶节点。

---

### 5.2 解法一：层序遍历判断

位置：`src/class12/Code01_IsCBT.java:17`，`src/class13/Code01_IsCBT.java:17`

核心变量：

- `leaf`：是否已经遇到过“不双全”节点

逻辑：

1. 层序遍历每个节点；
2. 如果某节点 `left == null && right != null`，直接不是完全二叉树；
3. 如果之前已经进入 `leaf == true` 状态，但当前节点还有孩子，也不是完全二叉树；
4. 如果当前节点左右孩子不双全，就把 `leaf = true`。

### 5.3 解法二：树形 DP

位置：`src/class12/Code01_IsCBT.java:53`，`src/class13/Code01_IsCBT.java:51`

Info 设计：

```java
public static class Info {
    public boolean isFull;
    public boolean isCBT;
    public int height;
}
```

当前子树要向上汇报：

- 是否是满二叉树
- 是否是完全二叉树
- 高度是多少

### 5.4 为什么这题要同时维护 isFull 和 isCBT

因为“完全二叉树”这个条件，单靠高度不够判断。

父节点想判断自己是不是完全二叉树时，需要知道左右子树分别属于哪种形态：

- 左满右满，且等高
- 左完全右满，且左高一层
- 左满右满，且左高一层
- 左满右完全，且等高

所以必须带上：

- `isFull`
- `isCBT`
- `height`

### 5.5 这题的学习重点

这题的本质不是“背四种情况”，而是理解：

> 完全二叉树是一个依赖左右子树结构类型和高度关系的判断题。

父节点能不能成为 CBT，取决于：

- 左右子树是不是 Full / CBT
- 左右高度差是多少
- 缺口是不是只能出现在最右下区域

这是典型的“分类讨论型树 DP”。

## 6. Code02_IsBST：判断搜索二叉树

文件：`src/class12/Code02_IsBST.java`

---

### 6.1 题目本质

搜索二叉树（BST）的定义：

- 左子树所有节点都小于根
- 右子树所有节点都大于根
- 左右子树也都必须是 BST

### 6.2 解法一：中序遍历

位置：`src/class12/Code02_IsBST.java:17`

BST 的一个经典性质：

> 中序遍历结果严格递增。

代码做法：

1. 先中序遍历存进数组；
2. 再检查数组是否严格升序。

这是最直观的验证方法。

### 6.3 解法二：树形 DP

位置：`src/class12/Code02_IsBST.java:40`

Info 设计：

```java
public static class Info {
    public boolean isBST;
    public int max;
    public int min;
}
```

为什么是这三个量？

因为父节点判断 BST，需要知道：

- 左子树是不是 BST
- 右子树是不是 BST
- 左子树最大值是否 `< x.value`
- 右子树最小值是否 `> x.value`

所以左右子树必须把：

- 自己是不是 BST
- 自己的最大值
- 自己的最小值

报上来。

### 6.4 这题非常重要的思维方式

这道题是树形 DP 入门模板题。

因为它非常清晰地展示了：

> 父节点做判断时，只关心那些“足够决定结果的信息”。

不需要整棵左树的所有节点，只要：

- 它是否有序（isBST）
- 它的边界值（max / min）

这就是树 DP 的精髓：

> **把复杂子树压缩成少量关键信息。**

## 7. Code03_IsBalanced：判断平衡二叉树

文件：`src/class12/Code03_IsBalanced.java`

---

### 7.1 平衡二叉树定义

对于任意节点：

- 左右子树都是平衡的
- 左右高度差不超过 1

### 7.2 解法一：借助外部布尔变量

位置：`src/class12/Code03_IsBalanced.java:15`

这版代码用 `boolean[] ans` 保存全局答案：

- 递归返回高度
- 一旦发现某节点左右高度差超过 1，就把 `ans[0] = false`

这是比较常见的“递归返回一个值，顺便借外部变量记录状态”的写法。

### 7.3 解法二：标准树形 DP

位置：`src/class12/Code03_IsBalanced.java:34`

Info 设计：

```java
public static class Info {
    public boolean isBalanced;
    public int height;
}
```

父节点只需要两类信息：

- 左右子树各自是否平衡
- 左右子树各自高度是多少

于是当前节点：

- `height = max(left.height, right.height) + 1`
- `isBalanced = left.isBalanced && right.isBalanced && abs(left.height - right.height) <= 1`

### 7.4 这题的意义

这题说明：

> 如果题目条件本身就是“左边满足 + 右边满足 + 当前点再做一次合并判断”，那几乎就是树形 DP。

这也是很多树题的第一反应模板。

## 8. Code04_IsFull：判断满二叉树

文件：`src/class12/Code04_IsFull.java`

---

### 8.1 满二叉树定义

满二叉树要求每一层都满。

如果树高为 `h`，节点数必须满足：

```text
nodes = 2^h - 1
```

### 8.2 解法一：分别求高度和节点数

位置：`src/class12/Code04_IsFull.java:15`

做法：

1. 递归求高度 `h(head)`
2. 递归求节点数 `n(head)`
3. 判断 `(1 << height) - 1 == nodes`

### 8.3 解法二：一次递归同时返回

位置：`src/class12/Code04_IsFull.java:38`

Info 设计：

```java
public static class Info {
    public int height;
    public int nodes;
}
```

当前节点：

- `height = max(left.height, right.height) + 1`
- `nodes = left.nodes + right.nodes + 1`

最后统一判断：

```java
(1 << all.height) - 1 == all.nodes
```

### 8.4 这题的重点

这题虽然简单，但非常适合理解：

> **Info 不一定非得带真假判断，也可以只带“中间统计量”。**

也就是说，树形 DP 不只是“返回是否满足条件”，还可以返回：

- 高度
- 节点数
- 最大值 / 最小值
- 距离
- 最大快乐值
- 最大 BST 大小

这些都是“可供父节点继续计算的素材”。

## 9. Code06_MaxDistance：求二叉树最大距离

文件：`src/class12/Code06_MaxDistance.java`

---

### 9.1 什么是最大距离

这份代码里的“距离”按节点数计算。

例如：

- 同一个节点到自己，距离为 1
- 一条路径经过 5 个节点，距离就是 5

最大距离就是：

> 任意两个节点之间路径长度（按节点数）的最大值

也就是树的“直径”问题。

### 9.2 解法一：暴力枚举任意两点

位置：`src/class12/Code06_MaxDistance.java:19`

做法：

1. 先收集所有节点；
2. 建立每个节点的父指针表；
3. 枚举任意两个节点；
4. 用公共祖先思路算它们距离；
5. 取最大值。

这个版本主要用于对数器验证。

### 9.3 解法二：树形 DP

位置：`src/class12/Code06_MaxDistance.java:122`

Info 设计：

```java
public static class Info {
    public int maxDistance;
    public int height;
}
```

父节点为什么需要这两个量？

因为以 `x` 为头的树，最大距离只可能来自三种情况：

1. 完全在左子树里
2. 完全在右子树里
3. 经过当前节点：`left.height + right.height + 1`

于是：

```java
p1 = leftInfo.maxDistance;
p2 = rightInfo.maxDistance;
p3 = leftInfo.height + rightInfo.height + 1;
maxDistance = max(p1, p2, p3);
```

同时当前树高度仍然是：

```java
height = max(left.height, right.height) + 1;
```

### 9.4 这题的经典性

这题非常典型，因为它体现了树 DP 的另一个常见套路：

> 全局最优值 = 左树内部最优 / 右树内部最优 / 经过当前节点的最优 三者取最大。

以后很多题都会长成这个样子。

## 10. Code02_MaxSubBSTHead：最大搜索子树的头节点

文件：`src/class13/Code02_MaxSubBSTHead.java`

---

### 10.1 题目本质

在一棵普通二叉树中，可能只有某个局部子树是 BST。

题目要求：

> 找到“最大的 BST 子树”的头节点。

这里的“最大”指节点数最多。

### 10.2 暴力思路

位置：`src/class13/Code02_MaxSubBSTHead.java:40`

- 如果整棵树是 BST，直接返回头；
- 否则递归去左树、右树中找；
- 比较左右结果谁更大。

### 10.3 树形 DP 思路

位置：`src/class13/Code02_MaxSubBSTHead.java:52`

Info 设计：

```java
public static class Info {
    public Node maxSubBSTHead;
    public int maxSubBSTSize;
    public int min;
    public int max;
}
```

父节点需要的信息是：

- 左右子树中，最大的 BST 头是谁
- 左右子树中，最大的 BST 有多大
- 左右整棵子树的最大值、最小值

### 10.4 当前节点如何判断自己能不能成为 BST 头

判断条件：

1. 左子树必须整体是 BST
2. 右子树必须整体是 BST
3. 左子树最大值 `< x.value`
4. 右子树最小值 `> x.value`

代码里判断“左子树整体是不是 BST”的方式很巧：

```java
leftInfo.maxSubBSTHead == X.left
```

意思是：

- 如果左子树里最大的 BST 头，恰好就是左孩子本身，
- 说明左子树整棵树就是 BST。

右树同理。

如果当前节点不能把左右连成一整棵 BST，
那么答案就在：

- 左树最大 BST
- 右树最大 BST

之间选更大的。

### 10.5 这题的价值

这题是前面 BST 判断题的升级版。

它说明：

> 有些题不只是问“是不是”，而是问“最优解是多少/在哪里”。

这时 Info 就要同时包含：

- 结构合法性信息
- 边界信息
- 最优解信息

这是树形 DP 很重要的进阶。

## 11. Code03_lowestAncestor：最低公共祖先

文件：`src/class13/Code03_lowestAncestor.java`

---

### 11.1 题目本质

给定二叉树头节点 `head`，以及两个节点 `a` 和 `b`，求它们的最低公共祖先（LCA）。

### 11.2 解法一：父指针表

位置：`src/class13/Code03_lowestAncestor.java:19`

思路：

1. 先建立每个节点到父节点的映射；
2. 从 `o1` 一路往上走，把所有祖先放到集合中；
3. 再从 `o2` 一路往上走；
4. 第一个进入集合的点，就是最低公共祖先。

这是非常直观的做法。

### 11.3 解法二：树形 DP

位置：`src/class13/Code03_lowestAncestor.java:52`

Info 设计：

```java
public static class Info {
    public boolean findA;
    public boolean findB;
    public Node ans;
}
```

含义：

- 当前子树里有没有找到 `a`
- 当前子树里有没有找到 `b`
- 如果已经确定最低公共祖先是谁，就记录在 `ans`

### 11.4 当前节点怎么合并信息

先收左右信息：

- `findA = (x == a) || left.findA || right.findA`
- `findB = (x == b) || left.findB || right.findB`

然后分情况：

1. 如果左子树已经算出了答案，直接沿用左边答案；
2. 否则如果右子树已经算出了答案，直接沿用右边答案；
3. 否则，如果当前子树已经同时发现了 `a` 和 `b`，那当前节点就是答案。

### 11.5 这题的本质理解

这题特别值得体会，因为它不是简单的数值型 DP，而是“状态汇报型 DP”。

子树向上汇报的不是一个数字，而是：

- 找没找到目标 A
- 找没找到目标 B
- 有没有已经确定好的答案

这说明树形 DP 的返回值可以非常灵活。

### 12.1 class12 更像基础模板训练

## 13. 这些题里最值得背下来的 Info 设计

下面这张表建议重点记。

| 题目 | Info 设计 | 为什么需要这些信息 |
| --- | --- | --- |
| 判断 BST | `isBST, max, min` | 判断左右是否是 BST，且边界值是否满足 BST 条件 |
| 判断平衡树 | `isBalanced, height` | 要知道左右是否平衡，以及高度差 |
| 判断满二叉树 | `height, nodes` | 用节点数和高度关系判断是否满 |
| 判断完全二叉树 | `isFull, isCBT, height` | 完全二叉树依赖结构类型和高度关系 |
| 最大距离 | `maxDistance, height` | 答案可能在左、右、或经过当前节点 |
| 最大 BST 头 | `maxSubBSTHead, maxSubBSTSize, min, max` | 既要知道最优解，也要知道能否与当前节点拼成 BST |
| 最低公共祖先 | `findA, findB, ans` | 要知道目标是否出现，以及答案是否已在子树中产生 |

你会发现：

> **Info 的内容，永远服务于父节点的决策。**

这句话非常关键。

## 14. 做树形 DP 的通用思考顺序

以后遇到新树题，可以按这个顺序思考。

### 第一步：假设左树和右树答案已知

问自己：

> 如果左边的信息和右边的信息我都拿到了，那么当前节点怎么得出答案？

### 第二步：反推子树应该返回什么

如果父节点需要判断某件事，就反推左右子树必须提供哪些信息。

例如：

- 要判断 BST，就要 max/min
- 要判断平衡，就要 height
- 要找最优 BST，就要 size 和 head
- 要找祖先，就要 findA/findB/ans

### 第三步：列出当前节点所有可能情况

很多树题卡在这里。

比如最大距离：

- 左树内部
- 右树内部
- 经过当前节点

比如完全二叉树：

- 左满右满等高
- 左完全右满，左高一层
- 左满右满，左高一层
- 左满右完全，等高

### 第四步：写 base case

空树返回什么非常关键。

比如：

- BST 判断中，空树返回 `null`，让上层单独处理
- 平衡树里，空树返回 `(true, 0)`
- 完全二叉树里，空树返回 `(isFull=true, isCBT=true, height=0)`

base case 是否顺手，决定代码是否好写。

## 16. 容易混淆的几个概念

### 16.1 满二叉树 vs 完全二叉树

- **满二叉树**：每层都满
- **完全二叉树**：最后一层可以不满，但必须从左往右连续

关系：

- 满二叉树一定是完全二叉树
- 完全二叉树不一定是满二叉树

### 16.2 BST 判断 vs 最大 BST 子树

- `IsBST`：问整棵树是不是 BST
- `MaxSubBSTHead`：问整棵树内部，最大的 BST 子树在哪里

后者明显更难，因为：

- 不只是判断合法性
- 还要维护最优解

### 16.3 高度 vs 距离

- **高度**：从当前节点往下，到最深节点的层数
- **最大距离**：树中任意两个节点路径上的节点数最大值

高度是局部信息，最大距离是全局最优。

### 16.4 深度 vs 高度

- **深度**：从根往下看当前节点在第几层
- **高度**：从当前节点往下看还能延伸几层

一个是“从上往下量”，一个是“从下往上量”。

## 20. 最终总结

class12~class13 的二叉树代码，表面上看是在做很多不同题目，但底层几乎都在训练同一件事：

> **站在当前节点视角，向左右子树要信息，再把信息整合成自己的 Info 返回上去。**

如果你真正学会了这套方法，那么你收获的不只是几道题，而是一个通用能力：

- 会拆树问题

- 会做分类讨论
- 会把局部信息合成为全局答案

所以，这两章最核心的学习目标可以概括成一句话：

> **树形 DP 的关键，不是递归，而是 Info 的设计。**
